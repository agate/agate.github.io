# honghao.me

Hong, Hao's personal site: projects and thoughts. Astro static site, deployed to GitHub Pages (`https://honghao.me`) by `.github/workflows/deploy.yml` on every push to `main`.

Three things define this site and must survive every change:

1. **Isometric line-art illustrations** — every picture is a precise isometric line drawing of a real object.
2. **One typographic system** — serif headings, sans body, mono metadata, on a near-white ground with hairline rules.
3. **Full English + Chinese, switched by a toggle** — every visible string exists in both languages; never mixed.

The style comes from https://skills.wheresryan.sh/anatomy/how-i-built-it (near-white ground, ink-black hairlines, numbered sections, isometric figures drawn by code rather than by hand). When in doubt, look at that page and at the live site.

## Domain, author name, and links home

- `site.config.mjs` is the only place that names the domain (`DOMAIN`, `SITE_URL`), the author (`AUTHOR`), and the GitHub account. `astro.config.mjs` and all pages import from it. Never hard-code `honghao.me`, the author's name, or `github.com/agate` in components.
- The author's name is **`Hong, Hao`** — surname first, marked with a comma — in **both** English and Chinese copy. Never write "Hong Hao" without the comma or "Hao Hong".
- Internal links are relative (`/`, `/#projects`, `/claude-lights/`), never `https://honghao.me/...`, so a domain change needs no link edits.
- **Every page's footer links back to the main domain's home page** with a relative `href="/"`. `Base.astro` does this for this site. Sub-sites served under the same domain (GitHub Pages project pages from other `agate/*` repos, e.g. `agate/claude-lights` → `/claude-lights/`) must have the same footer link; see that repo's `site/index.html`.
- To change the domain: edit `DOMAIN` in `site.config.mjs`, update DNS, then set the new custom domain in this repo's **Settings → Pages** (the Actions deploy ignores CNAME files, so there is none in `public/`). Sub-sites follow automatically.

## Layout


## 1. Illustrations: isometric line art

All illustrations are generated by `scripts/gen_icons.py`. Do not hand-write SVG paths, and do not use emoji, icon libraries, raster images, or AI-generated images in their place.

### Choosing what to draw

Each project gets one real, physical object that stands for it. Work through these in order:

1. **Pick a concrete object, not an abstraction.** It must be something you could hold or put on a desk. Examples already on the site:
   - claude-lights → a traffic light (the app shows session states as lights)
   - AI Poetry → an unrolled hand scroll (classical poems and paintings were mounted together on scrolls, which matches "one poem, one painting")
   - zmk-corne → the two halves of a Corne split keyboard joined by a cable
   - Next → an empty dashed box (the next project is not built yet)
2. **Tie the object's details to the project's meaning.** The scroll has vertical columns of short dashes because classical poems are written in vertical columns; the red square is a seal, as on Chinese calligraphy and painting. The traffic light's lit lamp uses claude-lights' own "done" color.
3. **It must read at 160×130.** Prefer objects with a strong silhouette. Moons, inkstones, or abstract shapes are hard to recognize at icon size.
4. **Cut any part that does not read.** A brush was once added next to the scroll; at icon size it looked like a stick, so it was removed. If a part needs explaining, delete it.

### Drawing rules

- **Projection:** true isometric (30°). In the `Iso` class, `x` runs to the lower right, `y` to the lower left, and `z` straight up. Build every shape from `box`, `circle`, `cylinder_y`, `poly`, and `line`; add a new primitive to `Iso` if needed rather than writing raw paths.
- **Line:** ink `#171717`, 1px, round joins and caps.
- **Faces:** solids are shaded with exactly three tones — top `#ffffff`, `+y` (lower-left) face `#f1f1f1`, `+x` (lower-right) face `#e6e6e6`.
- **Order:** draw back to front (painter's order) so nearer fills cover hidden edges. Do not draw hidden edges, except dashed outlines for something that does not exist yet (the "Next" box).
- **Accent:** at most one accent color per icon, and only where it carries meaning (a lit lamp, a seal). Use one of: bluish-green `#009e73`, vermillion `#d55e00`, amber `#e69f00`, seal red `#c0392b`. Pale tints of these (alpha `33`) are allowed for "off" states.
- **No** gradients, shadows, blur, filters, or text inside icons.
- **Size:** every icon is `g.svg(160, 130, label)`, which auto-fits and centers the drawing. Always give an English `aria-label` describing the object.
- Annotations such as glow rays may use a dashed accent stroke (`stroke-dasharray="2 2"`).

### Adding a new icon

1. Add a function to `scripts/gen_icons.py` and register it in the `__main__` dict.
2. Run `python3 scripts/gen_icons.py` — it writes `src/icons/<name>.svg`.
3. Import it with `?raw` in `src/data/projects.ts`.
4. Render it and look at it (see Verify). Fix clipping, misread parts, or strokes that look wrong. Strokes along the iso axes read as diagonals, so a "+" must be drawn screen-aligned (see `next_box`).
5. Commit both the script change and the generated SVG.

## 2. Typography and visual style

- Fonts are tokens in `src/styles/global.css`. Components use only `var(--head)`, `var(--body)`, and `var(--mono)` — never a literal font-family.
  - English: headings Instrument Serif, body Inter.
  - Chinese: LXGW WenKai (霞鹜文楷) for headings and body, chosen for its classical, hand-copied-book feel. Chinese body text lists Inter first so Latin words inside it (Claude Code, AI) stay in Inter; headings use WenKai alone, because Instrument Serif has no bold and the 600-weight card titles would be faux-bolded.
  - Metadata (dates, section numbers, tags, nav, footer): JetBrains Mono, 11px, `letter-spacing: .04em`, color `var(--muted)`, via the `.mono` class.
- `--head` and `--body` switch automatically with the language; do not add per-language font rules in components.
- Headings are weight 400 (Instrument Serif has only 400). Chinese headings may use 600 where an English heading would be visually heavier.
- Chinese text runs slightly smaller with taller line height than English. Follow the existing `:global(html[data-lang='zh'])` overrides when adding a new text style.
- Any new font family must be added to the Google Fonts `<link>` in `Base.astro` and as a token in `global.css`. The one exception is LXGW WenKai, loaded from jsDelivr (`lxgw-wenkai-webfont`, regular + bold only): Google Fonts has only the Traditional build (`LXGW WenKai TC`), which centers `，。` mid-line instead of placing them low-left as Simplified Chinese does.
- Colors come only from the `:root` tokens (`--ground`, `--ink`, `--soft`, `--muted`, `--faint`, `--rule`) plus the icon accents above.
- Structure is drawn with 1px `var(--rule)` hairlines and dotted `var(--faint)` list separators. No box shadows, no rounded cards, no colored backgrounds. The only rounded elements are pill tags (`.tag`, `.tag.live`, `.tag.dash`) and the language toggle.
- Page sections are numbered `01`, `02`, … in mono to the left of the heading (`.sec` grid on the home page).
- Layout must work at 390px phone width: `.wrap` gives a 16px gutter under 640px, grids collapse to one column, and nothing scrolls horizontally.

## 3. English and Chinese

The language toggle is client-side. Both languages are in the HTML; CSS hides the inactive one:

```css
html[data-lang='en'] [lang='zh'],
html[data-lang='zh'] [lang='en'] { display: none !important; }
```

Rules:

- **Every user-visible string is written twice**, as sibling elements: `<span lang="en">…</span><span lang="zh">…</span>` (or `h1`, `p`, etc.). This includes nav, headings, body copy, buttons, stats, dates, notes, and the 404 page.
- **Never mix languages in one string.** The English version is all English, the Chinese version is all Chinese. Proper nouns stay as they are in both (claude-lights, Claude Code, ZMK, Corne, GitHub, AI, and the author name from `AUTHOR`).
- Chinese copy uses full-width punctuation (，。：「」).
- Data is shaped `{ en: string; zh: string }` (see `Project` in `src/data/projects.ts`). Render both fields.
- Dates go through `formatDate(date, lang)` and are rendered once per language.
- Posts live in `src/content/thoughts/<slug>/en.md` and `zh.md`. Write both when possible. If only one exists, the post page shows it under both toggles with a "only available in …" note; keep that behavior.
- Keep the language mechanism as it is: the inline pre-paint script in `Base.astro` (priority: `?lang=` URL parameter, then `localStorage` key `lang`, then `navigator.language`), and `LangToggle.astro`, which saves the choice. Do not switch to Astro i18n routing (`/zh/…` URLs).
- Text inserted by client-side JavaScript must also exist in both languages.
- `aria-label`s on icons are English only.

## Verify before calling a change done

1. `npm run build` passes.
2. Screenshot and look at the result in both languages, at desktop and phone width. Headless Chrome cannot make a viewport narrower than 500px, so load phone width inside a 390px iframe:

   ```sh
   cd dist && python3 -m http.server 4399 &
   CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
   "$CH" --headless=new --hide-scrollbars --virtual-time-budget=6000 --window-size=1100,1700 \
     --screenshot=/tmp/en.png "http://localhost:4399/?lang=en"
   echo '<iframe src="/?lang=zh" style="width:390px;height:1900px;border:0"></iframe>' > m.html
   "$CH" --headless=new --hide-scrollbars --virtual-time-budget=6000 --window-size=500,1900 \
     --screenshot=/tmp/zh-mobile.png http://localhost:4399/m.html
   rm m.html
   ```

   Check: icons are not clipped and read as their object; the inactive language never shows; nothing overflows at 390px.
3. For a new icon, also render it alone at 2× and look at it.
